# Plan 11-06: Parties Tab + PartyView Screen (4 Tabs)

## Goal
Replace the Parties tab placeholder in the directory with tinted party cards (party color fill, logo, seat count), add a PartyView screen with 4 tabs (Info, Members, Stats, Manifesto), and make the party pill on MP profiles clickable to navigate to PartyView.

## Tasks

### Party stats build script (goveye-data repo)
1. Create `goveye-data/build_party_stats.py` following the per-API build script pattern. Fetch party stats from two sources (D-07: hybrid):
   - Parliament election results API: `api.parliament.uk/uk-general-elections/parties/{id}` — vote share, seats won per election
   - Wikipedia: party description (intro paragraph, D-08), founded date, current leader
2. Implement `fetch_wikipedia_description(party_name: str) -> str` — scrape the first 1-2 sentences of each party's Wikipedia article using `requests.get()` + `BeautifulSoup` (already a dependency from `build_debates.py`). Extract the intro paragraph from the Wikipedia HTML.
3. Implement `build_party_stats_table(conn)` — create `party_stats` table: `partyId INTEGER PRIMARY KEY, description TEXT, foundedYear TEXT, leaderName TEXT, lastElectionVoteShare REAL, lastElectionSeats INTEGER, lastElectionYear INTEGER, lastUpdated INTEGER`.
4. Set `TABLE_NAMES = ["party_stats"]`. Add `--mps-db` argument to read party IDs.
5. Create `goveye-data/.github/workflows/update-party-stats.yml` — cron `0 10 * * 1` (weekly, after mp-links), publish to `party-stats-latest`.

## Risks
- **Wikipedia scraping fragility**: Wikipedia HTML structure may change, breaking the description scraper. Mitigation: defensive parsing with `BeautifulSoup`, log failures, continue with `description = null` if scraping fails. The app handles null description gracefully.
- **Party logo licensing**: Some Wikipedia SVG logos may be non-free or trademarked. Mitigation: verify usage rights for each logo. If a logo can't be used, fall back to abbreviation text (D-06). Document which logos are used and their license status.
- **SVG to VectorDrawable conversion**: Not all SVG features are supported by Android VectorDrawable. Mitigation: use `svg2vector` CLI tool or manually simplify SVGs. Test each logo renders correctly on device.
- **PartyView navigation complexity**: Adding a new route to the Nav3 graph requires updating `GovEyeApp.kt`, `Routes.kt`, and the deep link handler. Mitigation: follow the exact pattern of existing routes (e.g., `ProfileRoute`, `BillDetailRoute`).
- **Paged list in Members tab**: Reusing Paging 3 with a party-filtered query requires a new `PagingSource` in `MpDao`. Mitigation: follow the existing `pagingSource()` pattern in `MpDao.kt` (line 16).
