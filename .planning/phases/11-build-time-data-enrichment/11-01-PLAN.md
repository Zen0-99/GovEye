# Plan 11-01: MNIS Biographical Data Build Script + Android Entity

## Goal
Fetch MNIS biographical data (maiden speeches, government/opposition posts, honours, DOB, committee chairing) for all 650 MPs at build time, store in a new `bio_data` table in the bundled DB, and merge MNIS posts into the existing career timeline on the MP profile.

## Tasks

### Build script (goveye-data repo)
1. Create `goveye-data/build_mnis.py` following the per-API build script pattern from `build_mps.py` and `build_interests.py` — seed/delta modes, checkpoint/resume, schema validation against `schemas/bundled_schema.json`.
2. Define the MNIS API base URL: `http://data.parliament.uk/membersdataplatform/services/mnis/members/query/`. Use the `memberquery.aspx` endpoint with output params `FullBiog|Committees|GovernmentPosts|Honours|MaidenSpeeches`.
3. Implement `fetch_mnis_batch(mp_ids: list[int]) -> list[dict]` — fetch MNIS XML for a batch of up to 50 MP IDs (join IDs with commas in the URL: `ids={id1},{id2},...`). Use `api_get()` from `api_helper.py` with `API_DELAY` between batches. Parse XML using `xml.etree.ElementTree` (stdlib, no extra deps).
4. Implement `parse_mnis_member(xml_element) -> dict` — extract from the XML: `Member_Id`, `DateOfBirth`, `MaidenSpeeches/MaidenSpeech/Date`, `GovernmentPosts/GovernmentPost` (title, dept, startDate, endDate), `OppositionPosts/OppositionPost` (same structure), `Honours/Honour` (title, date), `Committees/Committee` (name, startDate, endDate, chair flag). Store posts and honours as JSON arrays (via `json.dumps()`).
5. Implement `build_bio_data_table(conn)` — create the `bio_data` table with columns: `mpId INTEGER PRIMARY KEY, maidenSpeechDate TEXT, dateOfBirth TEXT, townOfBirth TEXT, countryOfBirth TEXT, honoursJson TEXT, postsJson TEXT, committeesJson TEXT, lastUpdated INTEGER`.
6. Implement `insert_bio_data(conn, rows)` — batch insert using `BATCH_SIZE` from `api_helper.py`.
7. Implement seed mode: fetch all 650 MP IDs from the MPs DB (passed via `--mps-db`), fetch MNIS data in batches of 50, insert into `bio_data`.
8. Implement delta mode: copy previous DB, fetch all MPs, upsert changed rows (compare `lastUpdated`).
9. Set `TABLE_NAMES = ["bio_data"]` for `diff_db.py` and `manifest.py` compatibility.
10. Add `--mps-db` required argument (path to `mps.db`) to read MP IDs for fetching.

## Risks
- **MNIS API reliability**: The MNIS API can be slow or return errors for individual MPs. Mitigation: batch with retries via `api_get()`, log failures, continue on partial failure (same pattern as `build_interests.py`).
- **XML parsing complexity**: MNIS XML has nested structures for posts/honours/committees. Mitigation: use `xml.etree.ElementTree` with defensive parsing (skip missing elements, log warnings for unexpected structures).
- **DB version bump**: Adding a new entity bumps BundledDatabase from v4 to v9 (coordinated across Phase 11). Existing users with v4 DB will trigger `fallbackToDestructiveMigration` — acceptable since the DB is re-downloaded from patch streams. Mitigation: verify the first-launch merge handles the new `bio_data` table correctly.
- **Date format mismatch**: MNIS dates may be in different formats (ISO vs UK). Mitigation: normalize to ISO `YYYY-MM-DD` in the build script before storing.
