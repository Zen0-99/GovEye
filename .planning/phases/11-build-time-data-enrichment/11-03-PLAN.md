# Plan 11-03: ParlParse Social Links Build Script + Android Entity

## Goal
Download ParlParse `people.json`, extract social media links and Wikipedia URLs for all MPs, store in a new `mp_links` table in the bundled DB, and display a social links icon row on MP profiles.

## Tasks

### Build script (goveye-data repo)
1. Create `goveye-data/build_parlparse.py` following the per-API build script pattern from `build_mps.py` — seed/delta modes, schema validation against `schemas/bundled_schema.json`.
2. Define the ParlParse download URL: `https://parser.theyworkforyou.com/people.json` (D-10: download JSON only, no git clone). Download using `requests.get()` with retry logic from `api_helper.py`.
3. Implement `parse_people_json(json_path: str) -> list[dict]` — parse the Popolo-format JSON. Each person has `id`, `name`, `identifiers` (list of `{scheme, identifier}`), and `links` (list of `{url, note}`). Extract per person:
   - `twitterHandle` from `identifiers` where `scheme == "twitter"` (or from `links` where `note == "twitter"`)
   - `facebookUrl` from `links` where `note == "facebook"`
   - `instagramUrl` from `links` where `note == "instagram"`
   - `linkedinUrl` from `links` where `note == "linkedin"`
   - `wikipediaUrl` from `links` where `note == "wikipedia"`
   - `personalWebsiteUrl` from `links` where `note == "personal"` (or `note == "website"`)
4. Implement `match_parlparse_person(person_id: str, person_name: str, mps_db_path: str) -> int` — match ParlParse persons to Parliament member IDs. First try ParlParse person ID (format `uk.org.publicwhip/person/{id}`) against the MPs DB if a TWFY person ID column exists. Fall back to name matching using the `_strip_honorifics()` + `build_name_lookup()` pattern from `build_debates.py` (lines 44-115). Return 0 if no match.
5. Implement `build_mp_links_table(conn)` — create the `mp_links` table: `mpId INTEGER PRIMARY KEY, twitterHandle TEXT, facebookUrl TEXT, instagramUrl TEXT, linkedinUrl TEXT, wikipediaUrl TEXT, personalWebsiteUrl TEXT, lastUpdated INTEGER`.
6. Implement `insert_mp_links(conn, rows)` — batch insert using `BATCH_SIZE`.
7. Implement seed mode: download `people.json`, parse, match to MPs, insert all links.
8. Implement delta mode: copy previous DB, download latest `people.json`, upsert all rows.
9. Set `TABLE_NAMES = ["mp_links"]` for `diff_db.py` and `manifest.py` compatibility.
10. Add `--mps-db` required argument for name matching.

5. Open an MP profile → Profile tab → verify a row of social media icons appears (if the MP has links in the DB). Click each icon → verify it opens the correct URL in the browser.

## Risks
- **ParlParse person ID mismatch**: ParlParse person IDs (`uk.org.publicwhip/person/{id}`) may not directly map to Parliament member IDs. Mitigation: name-based matching as fallback (proven pattern from `build_debates.py`). Log match rate; if below 80%, investigate.
- **people.json download size**: The file is ~5-10MB (D-10). Mitigation: download once, parse in memory. No need for streaming since the file is small.
- **Link URL validity**: Some links may be outdated or broken. Mitigation: the app opens URLs via `Intent.ACTION_VIEW` with `try/catch` — broken links show a toast or silently fail, no crash.
- **Twitter/X rebrand**: Twitter URLs may now be `x.com` instead of `twitter.com`. Mitigation: store the handle, construct the URL at display time as `https://x.com/{handle}` (or `https://twitter.com/{handle}` as fallback).
