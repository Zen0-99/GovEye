### FTS query sanitization (Kotlin port of Odysseus Vault _sanitize_fts_query)
1. Create `core/domain/src/main/java/com/goveye/app/domain/search/FtsQuerySanitizer.kt` — `object FtsQuerySanitizer` with `fun sanitize(query: String): String?`. Port the Python `_sanitize_fts_query()` pattern from Odysseus Vault `session_search.py`:
   ```kotlin
   fun sanitize(query: String): String? {
       val tokens = mutableListOf<String>()
       val regex = Regex(""""([^"]+)"|[\w][\w._-]*""")
       for (match in regex.findAll(query)) {
           val phrase = match.groupValues[1]
           if (phrase.isNotEmpty()) {
               tokens.add("\"${phrase.replace("\"", "\"\"")}\"")
           } else {
               val token = match.value.trim('.', '_', '-')
               if (token.isNotEmpty()) {
                   tokens.add(if (token.any { it in "._-" }) "\"$token\"" else token)
               }
           }
       }
       return if (tokens.isEmpty()) null else tokens.joinToString(" ")
   }
   ```
   This strips FTS operators, quotes phrases, and produces safe MATCH syntax. Returns `null` if the query has no valid tokens (caller should skip the search).

2. Write unit tests for `FtsQuerySanitizer.sanitize()` in `core/domain/src/test/java/com/goveye/app/domain/search/FtsQuerySanitizerTest.kt` — test cases:

### Snippet highlighting (Compose AnnotatedString + SpanStyle)
3. Create `core/ui/src/main/java/com/goveye/app/ui/components/search/HighlightUtils.kt` — `object HighlightUtils` with `fun highlightSearchTerms(text: String, query: String, highlightColor: Color): AnnotatedString`. Port the Odysseus Vault `_hlSearch()` pattern (split on whitespace, longest-first, wrap each match):
   ```kotlin
   fun highlightSearchTerms(text: String, query: String, highlightColor: Color): AnnotatedString {
       val terms = query.split(Regex("\\s+"))
           .filter { it.isNotBlank() }
           .sortedByDescending { it.length }
           .map { Regex.escape(it) }
       if (terms.isEmpty()) return AnnotatedString(text)
       val regex = Regex("(${terms.joinToString("|")})", RegexOption.IGNORE_CASE)
       return buildAnnotatedString {
           var lastEnd = 0
           for (match in regex.findAll(text)) {
               append(text.substring(lastEnd, match.range.first))
               withStyle(SpanStyle(background = highlightColor)) {
                   append(match.value)
               }
               lastEnd = match.range.last + 1
           }
           append(text.substring(lastEnd))
       }
   }
   ```
   Use `SpanStyle(background = highlightColor)` for the highlight — use `MaterialTheme.colorScheme.primary.copy(alpha = 0.3f)` as the highlight color for a subtle tint that works in both light and dark themes.

### Manifesto search DAO queries
4. Add FTS4 search query to `ManifestoDao.kt` (created in 11-05). The query uses `snippet()` for context excerpts and `bm25()` for ranking:
   ```kotlin
   @Query("""
       SELECT pm.partyId,
              snippet(party_manifestos_fts4, 0, '<b>', '</b>', '...', 32) as snippetText,
              bm25(party_manifestos_fts4) as rank
       FROM party_manifestos_fts4
       JOIN party_manifestos pm ON pm.rowid = party_manifestos_fts4.rowid
       WHERE party_manifestos_fts4 MATCH :query
       AND pm.partyId = :partyId
       ORDER BY rank
       LIMIT 50
   """)
   suspend fun searchManifestoFts4(partyId: Int, query: String): List<ManifestoSearchResult>
   ```
   Note: `snippet()` returns text with `<b>` and `</b>` markers around matched terms. The UI strips these markers and applies `SpanStyle` highlighting instead (D-05: results-only list with highlighted terms).

## Risks
- **FTS5 availability on older devices**: FTS5 is available from API 21+ (Android 5.0), but some older devices may have a custom SQLite build without FTS5 support. Mitigation: `try/catch` around FTS5 queries, fall back to FTS4. The FTS4 table (via Room `@Fts4`) is always available.
- **snippet() marker parsing**: The `snippet()` function wraps matched terms in `<b>`/`</b>` markers. These must be stripped before applying Compose `SpanStyle` highlighting. Mitigation: simple `replace("<b>", "").replace("</b>", "")` before passing to `highlightSearchTerms()`. The highlighting is then applied by the Kotlin code, not by the FTS function.
- **bm25() availability**: `bm25()` is an FTS5 function. FTS4 doesn't have `bm25()` — it uses `matchinfo()` for ranking. Mitigation: the FTS4 query uses `bm25(party_manifestos_fts4)` which may fail on some Android versions. If it fails, fall back to no ranking (just `LIMIT 50` without `ORDER BY rank`). Test on both API 21+ and older devices.
- **Large manifesto text in memory**: Loading the full manifesto text (~25K words for Conservative) for snippet expansion is ~150KB in memory. Mitigation: only load when a snippet is tapped (lazy loading), and cache the result in the ViewModel so subsequent taps don't re-fetch.
- **Search debounce and UX**: 300ms debounce may feel sluggish for short queries. Mitigation: the debounce is in the ViewModel (same pattern as DirectoryScreen search), which is proven to feel responsive. The results list appears smoothly after the debounce.
- **Snippet context finding**: Finding the clean snippet text within the full manifesto text may fail if the snippet has been truncated or modified by `snippet()`. Mitigation: use fuzzy matching (find the longest common substring) or fall back to showing just the snippet without expanded context if the exact text isn't found.
