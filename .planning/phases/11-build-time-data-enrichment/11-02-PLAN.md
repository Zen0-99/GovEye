# Plan 11-02: IPSA Expenses Build Script + Android Entity

## Goal
Download IPSA expense claims CSV, parse and bucket into high-level categories, store in a new `expenses` table in the bundled DB, and display expense cards in the Interests tab on MP profiles.

## Tasks

### Build script (goveye-data repo)
1. Create `goveye-data/build_ipsa.py` following the per-API build script pattern from `build_interests.py` — seed/delta modes, checkpoint/resume, schema validation against `schemas/bundled_schema.json`.
2. Define the IPSA data source URL: `https://www.theipsa.org.uk/mp-costs/annual-claims/` (or the direct CSV download URL). Download the CSV file using `requests.get()` with retry logic from `api_helper.py`.
3. Define `IPSA_BUCKET_MAPPING` dictionary (D-09) mapping raw IPSA categories to high-level buckets:
   ```python
   IPSA_BUCKET_MAPPING = {
       "Staffing": "Staffing",
       "Office Costs": "Office",
       "Accommodation/Travel": "Travel",
       "Stationery": "Office",
       "Communications": "Office",
       "Equipment": "Office",
       "Staffing Travel": "Travel",
       "Family Travel": "Travel",
   }
   ```
   Implement `get_bucket(category: str) -> str` — look up the category, fall back to "Other" if not found. Follow the exact pattern of `get_bucket()` in `build_interests.py` (line 63-73).
4. Implement `parse_ipsa_csv(csv_path: str) -> list[dict]` — parse CSV with Python's `csv` module. Each row has: MP name, constituency, category, claim amount, date, status. Filter to `status == "Approved"` or equivalent. Convert amount to integer pence (multiply by 100, round — same as Phase 9 D-03 monetary parsing).
5. Implement `match_mp_name(name: str, mps_db_path: str) -> int` — match IPSA MP names to Parliament member IDs. Reuse the name matching pattern from `build_debates.py` (`_strip_honorifics()`, `build_name_lookup()`, `match_speaker()` — lines 44-115). Build a name→memberId lookup from `mps.db` using `nameDisplayAs` and `nameListAs` with honorific stripping. Return 0 if no match.
6. Implement `build_expenses_table(conn)` — create the `expenses` table: `id INTEGER PRIMARY KEY AUTOINCREMENT, mpId INTEGER, category TEXT, bucket TEXT, amountPence INTEGER, claimDate TEXT, status TEXT, lastUpdated INTEGER`.
7. Implement `insert_expenses(conn, rows)` — batch insert using `BATCH_SIZE`.
8. Implement seed mode: download CSV, parse, match names, insert all expenses.
9. Implement delta mode: copy previous DB, download latest CSV, upsert all rows (expenses can be amended — `INSERT OR REPLACE`).
10. Set `TABLE_NAMES = ["expenses"]` for `diff_db.py` and `manifest.py` compatibility.
11. Add `--mps-db` required argument (path to `mps.db`) for name matching.

## Risks
- **MP name matching edge cases**: IPSA CSV uses MP names that may differ from Parliament API names (name changes, typos, honorifics). Mitigation: reuse the proven `_strip_honorifics()` + `build_name_lookup()` pattern from `build_debates.py`. Log unmatched names for manual review. Consider fuzzy matching (Levenshtein distance) as a fallback if match rate is below 90%.
- **IPSA CSV format changes**: IPSA may change their CSV format or URL structure. Mitigation: defensive parsing with clear error messages, log the CSV header for debugging.
- **IPSA publish frequency**: IPSA publishes every 2 months, not weekly. Mitigation: set the workflow cron to monthly (`0 8 1 * *`) to avoid unnecessary runs.
- **Large CSV file**: The annual claims CSV may be large (650 MPs × multiple categories × 12 months). Mitigation: stream-parse with `csv.DictReader` instead of loading all rows into memory.
