# Plan 18-01: Python parser + DB schema for 16 structured interest fields

## Goal

Add a `parse_interest_summary()` function to `build_interests.py` that extracts 16 structured fields from the raw interest `summary` text, handling both Format A (simple/legacy single-line) and Format B (structured/modern multi-line with field labels). Add the 16 new nullable TEXT columns to the `interests` table schema, update both `build_interests.py` and `build_historical_interests.py` insert SQL, and rebuild the seed DB so it ships with fully structured data.

## Context

- The current `interests` table has 14 columns: `id, memberId, summary, categoryId, categoryNumber, categoryName, registrationDate, publishedDate, rectified, fieldsJson, lastUpdated, parsedAmountPence, currencyCode, bucket`.
- Research (18-RESEARCH.md) analyzed 45,359 entries: 33% are Format B (multi-line with `FieldName: Value` labels), 67% are Format A (single-line, category-specific patterns).
- The bundled schema JSON at `goveye-data/schemas/bundled_schema.json` drives table creation via `schema.py:create_database_with_tables()`. The Room-exported schema at `GovEye/core/data/schemas/.../24.json` must match (generated by Room when the entity changes in 18-02).
- `build_historical_interests.py` also inserts into the `interests` table (with a 1,000,000 ID offset) using the same 14-column INSERT SQL. It must be updated to include the 16 new columns (populated by the same parser where possible, NULL otherwise).
- Per goveye-data/AGENTS.md: this is a **transformation logic change** (new derived columns), so the seed DB rebuild requires a full `build_interests.py --mode seed` run because the new columns are populated at insert time from the parsed summary — they cannot be backfilled with a simple SQL UPDATE against the existing DB (the parser runs on the raw API summary text which is already in the DB, but the structured extraction is complex enough that re-running the parser via SQL is impractical). A seed rebuild is the cleanest path.

**Action:**

Add a new function `parse_interest_summary(summary, category_number)` that returns a dict with 16 keys (all defaulting to `None`):

```python
STRUCTURED_FIELDS = [
    "donorName", "paymentType", "paymentDescription", "donorStatus",
    "donorAddress", "donorCompanyIdentifier", "destination", "visitPurpose",
    "organisationName", "organisationDescription", "propertyLocation",
    "propertyType", "hoursWorked", "familyMemberName",
    "familyMemberRelationship", "familyMemberRole",
]
```

**Stage 1 — Format B detection and parsing:**
- Detect Format B: `summary` contains `\n` AND matches any known field label regex.
- Known field labels (case-insensitive): `Donor Name:`, `Payer Name:`, `Name of donor:`, `Payment Type:`, `Payment Description:`, `Purpose of visit:`, `Description:`, `Donor Status:`, `Donor Public Address:`, `Payer Public Address:`, `Donor Company Identifier:`, `Destination of visit:`, `Organisation Name:`, `Organisation Description:`, `Location:`, `Property Type:`, `Hours Worked:`, `Name:`, `Relationship:`, `Role:`.
- Split summary by `\n`, extract `FieldName: Value` pairs into a dict (strip whitespace, skip `Registration Date:`, `Published Date:`, `Parent interest details:` lines).
- Map extracted pairs to the 16 structured columns using a label→column mapping:
  - `Donor Name` / `Payer Name` / `Name of donor` → `donorName`
  - `Payment Type` → `paymentType`
  - `Payment Description` / `Purpose of visit` / `Description` → `paymentDescription`
  - `Donor Status` / `Donor status` → `donorStatus`
  - `Donor Public Address` / `Payer Public Address` → `donorAddress`
  - `Donor Company Identifier` → `donorCompanyIdentifier`
  - `Destination of visit` → `destination`
  - `Purpose of visit` → `visitPurpose` (only if not already mapped to `paymentDescription`)
  - `Organisation Name` → `organisationName`
  - `Organisation Description` → `organisationDescription`
  - `Location` → `propertyLocation`
  - `Property Type` → `propertyType`
  - `Hours Worked` → `hoursWorked`
  - `Name` → `familyMemberName` (for Cat 9/10) — note: for donor categories, `Name of donor` maps to `donorName`, not this
  - `Relationship` → `familyMemberRelationship`
  - `Role` → `familyMemberRole`

**Stage 2 — Format A parsing (category-specific regex):**
Only run if Stage 1 did not produce a `donorName` (or category-appropriate primary field). Use `category_number` to select the pattern:
- Cat `2`, `3`, `5`: `^(.+?)\s*-\s*£([\d,]+\.?\d*)` → `donorName` = group 1 (stripped)
- Cat `1.1`: `^Payment received on\s+(.+?)\s*-\s*£` → leave `donorName` None, set `paymentDescription` = full text (the "Payment received on DATE" part)
- Cat `1.2`: `^(.+?)\s*-\s*£` → `donorName` = group 1
- Cat `1`: Use full text as `paymentDescription` (job title / role description)
- Cat `4`: `^International visit to\s+(.+?)\s+between\s+(.+?)\s+and\s+(.+)$` → `destination` = group 1, `visitPurpose` = None (Format A visits have no purpose line)
- Cat `6`: `^(Residential|Commercial)\s+in\s+(.+)$` → `propertyType` = group 1, `propertyLocation` = group 2
- Cat `7`: `^Shares in\s+(.+)$` → `organisationName` = group 1
- Cat `8`: Use full text as `paymentDescription`
- Cat `9`: `^(.+?)\s+employed` → `familyMemberName` = group 1 (best-effort)
- Cat `10`: `^(.+?)\s+employed as` → `familyMemberName` = group 1 (best-effort)

**Stage 3 — Fallback:** If no pattern matches, return all-`None` dict. The `summary` column retains the full raw text.

**Acceptance criteria:**
- `parse_interest_summary("Guildford Labour Party - £3,675.00", "2")` returns `{"donorName": "Guildford Labour Party", ...all others None}`
- `parse_interest_summary("International visit to China between 05 January 2025 and 10 January 2025", "4")` returns `{"destination": "China", ...}`
- `parse_interest_summary("Residential in Greater London", "6")` returns `{"propertyType": "Residential", "propertyLocation": "Greater London", ...}`
- `parse_interest_summary("Shares in Endava Ltd", "7")` returns `{"organisationName": "Endava Ltd", ...}`
- A multi-line Format B summary with `Donor Name: Acme Corp\nPayment Type: Monetary\n...` extracts `donorName="Acme Corp"`, `paymentType="Monetary"`, etc.
- Unparseable text returns all-`None` (no fabricated data).
